# AGENTS.md — working in the Stufe repo

Guidance for AI agents (and humans) working on this project. Read this first.

## What this is

Stufe is a spaced-repetition trainer for German (a WaniKani + Bunpro analogue):
vocabulary and grammar as parallel SRS queues, drilled with active recall, with
audio. It is a static site — **no backend**.

Three parts:

| Path | What | Stack |
| --- | --- | --- |
| `web/` | the app (source) | Vite + React 18 + TypeScript + Tailwind + Radix/shadcn |
| `docs/` | the **built** app | output of `web/` — **never edit by hand** |
| `tools/` | the data pipeline | Python 3, standard library only |
| `content/` | hand-authored content | JSON |
| `data/` | the generated deck | JSON, committed |

Human documentation lives in **`documentation/`** (NOT `docs/`, which is the build).

## Golden rules

1. **`docs/` is build output.** `npm run build` (in `web/`) wipes and rewrites it.
   Never put source or documentation there. GitHub Pages serves `docs/`.
2. **Never edit `data/` by hand** — it is generated by `tools/` from `content/`.
3. **The deck is derived from open data.** Keep the licences correct:
   Tatoeba (CC BY 2.0 FR), german-nouns / Wiktionary (CC BY-SA 4.0),
   FrequencyWords (MIT). The combined `data/` files are CC BY-SA 4.0.
4. **Accessibility is enforced.** `web/e2e/a11y.spec.ts` runs axe over every
   screen and fails on *any* violation. See "Accessibility rules" below.
5. **TypeScript is strict** (`noUnusedLocals`, `noUnusedParameters`). `tsc --noEmit`
   runs in the build; unused imports break CI.
6. **Never rename a `data-act`-style contract without updating tests.** The e2e
   suite and a11y suite depend on roles/labels; keep them stable.

## Run, build, test

```bash
# app (dev) — sync-data runs first automatically
cd web && npm install && npm run dev        # http://localhost:5173

# app (production build -> ../docs)
cd web && npm run build

# unit tests (Vitest, pure logic in src/lib/*.test.ts)
cd web && npm run test:unit

# browser tests (Playwright smoke + axe a11y) against the built app
cd web && npm run build && npm run test:e2e

# pipeline + dataset tests (Python)
python3 -m unittest discover -s tests -v
```

CI (`.github/workflows/ci.yml`) runs the Python tests and the web
build/unit/e2e/a11y on every push and PR. Pages deploys `docs/` on `main`.

## Data pipeline (tools/)

```bash
cd tools
python3 fetch_sources.py     # frequency list, noun table, Tatoeba pairs (~30 MB)
python3 fetch_kaikki.py      # Wiktionary extract (~1.1 GB, for the core deck)
python3 build_frequency.py   # nouns/verbs/adjectives by frequency -> data/vocab_frequency.json
python3 build_conjugations.py# present/preterite/participle for curated verbs
python3 build_dataset.py     # merge content/ (+ generated) -> data/items.json, levels.json, reading.json, attribution.json
python3 import_anki.py --apkg X.apkg   # personal deck (gitignored)
```

Raw downloads land in `data/raw/` (gitignored). `build_dataset.py` merges
`data/vocab_frequency.json` and `data/vocab_personal.json` when present.

## Where code goes (web/src/)

- `lib/` — pure, unit-tested logic (no React). `stages`, `stats`, `projection`,
  `grade`, `srsCore`, `selectors`, `judge`, `tts`, `shuffle`, `store`, `data`,
  `theme`. **Put logic here, not in components**, and add a `*.test.ts`.
- `components/ui/` — shadcn-style primitives (Button, Card, Tabs, Select, Switch,
  Progress, Accordion, Chip). Prefer these over ad-hoc markup.
- `components/` — app-level components (e.g. `Art` for der/die/das colouring).
- `hooks/` — `useDeck` (data), `useProgress` (store), `useStudy` (session machine).
- `routes/` — one file per screen; wired in `App.tsx`.

State: the store is a tiny observable in `lib/store.ts`, read via
`useProgress()` (`useSyncExternalStore`). Progress/history/settings live in
`localStorage` under `stufe-progress-v2`.

## Naming convention (grammar groups)

Follow Bunpro: the **German pattern/formula is the title**, a short **English
function** is the subtitle, grouped level → lesson → point. E.g.
`Passiv: werden + Partizip II` — "passive voice". Keep group names consistent
across levels (do not switch to German-only names at C1/C2).

## Accessibility rules (must pass axe)

- Every screen has exactly one `<h1>` (use `sr-only` if visually hidden).
- Radix `Progress` needs an accessible name — pass `label="…"`.
- Radix `SelectTrigger` needs `aria-label="…"`.
- Do not use Radix `Tabs` as a bare toggle (it emits `aria-controls` for panels
  that may not exist) — use buttons with `aria-pressed`.
- Accordion headers render as `<h2>` (heading order).
- Buttons are real `<button>`s; never a bare clickable word.

## Environment: Windows + WSL (IMPORTANT)

The agent runs on Windows; the repo lives in WSL at
`~/projects/stufe`. Two recurring traps (see the `wsl-windows-env`
skill for detail):

1. **Files written via the UNC path become root-owned.** Author files to
   `<windows-temp>\...` and copy them in with
   `wsl -e bash -lc "cp <windows-temp> <dest>"` so they land as `ivaylo`.
2. **The PowerShell → WSL pipe mangles quoting** (`$VAR`, `$(...)`, quotes).
   Never inline complex bash — write a `.sh` script file and run
   `wsl -e bash -lc "bash /tmp/x.sh"`. Node is via `nvm`:
   `export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"`.

Run browser checks with the Playwright MCP against a static server
(`python3 -m http.server` on the folder), and clean up `.playwright-mcp/`
artifacts afterwards.

## Commit / issue conventions

- Small, focused commits. Reference the issue: `Closes #N` (auto-closes) or
  `Refs #N`. Commit messages via a file: `git commit -F /tmp/msg.txt` (never
  `-m "multi word"` through the pipe).
- Keep `TASKS.md` and `documentation/` in sync when behaviour changes.
- One logical change per commit; include the regenerated `data/` when content
  changes.

## North star: Bunpro + WaniKani

**Bunpro and WaniKani are the reference implementations.** When a design choice
is unclear, do what they do. The full rationale is in
[`decisions.md`](documentation/decisions.md); in short:

- **SRS is fixed-interval and staged** (Bunpro's 12 levels: Beginner → Adept →
  Seasoned → Expert → Master). **Not** adaptive — do **not** add SM-2/FSRS
  (Bunpro explicitly rejected FSRS). #75 is closed as not planned.
- **Reviews are cloze-driven and varied** — multiple example sentences, a
  separate `vocab-cloze` track; the analogous WaniKani meaning/reading split is
  our gender/plural/case tracks.
- **Decks follow CEFR** (frequency-anchored approximation; see ADR-4), with
  custom topic decks a later possibility.
- **"Difficulty" is automatic** (stage + leeches/ghosts), never a manual Anki
  rating.
- **Burned items** (Master) leave the queue; Extra study re-drills them.

## What this is

A spaced-repetition trainer for German (WaniKani + Bunpro analogue): vocabulary
and grammar as parallel SRS queues, active recall, audio. Static site — **no
backend**.

| Path | What | Stack |
| --- | --- | --- |
| `web/` | the app (source) | Vite + React 18 + TypeScript + Tailwind + Radix/shadcn |
| `docs/` | the **built** app | output of `web/` — **never edit by hand** |
| `tools/` | the data pipeline | Python 3, standard library only |
| `content/` | hand-authored content | JSON |
| `data/` | the generated deck | JSON, committed |
| `documentation/` | human docs | Markdown |

## Golden rules

1. **`docs/` is build output.** `npm run build` (in `web/`) wipes/rewrites it.
   GitHub Pages serves `docs/`. Human docs live in `documentation/`.
2. **Never edit `data/` by hand** — it is generated by `tools/` from `content/`.
3. **Keep licences correct.** Tatoeba (CC BY 2.0 FR), german-nouns/Wiktionary
   (CC BY-SA 4.0), FrequencyWords (MIT); combined `data/` is CC BY-SA 4.0. Do not
   vendor non-redistributable lists into `data/` (ADR-13).
4. **Accessibility is enforced** — `web/e2e/a11y.spec.ts` fails on any axe
   violation. Rules: [`documentation/testing.md`](documentation/testing.md).
5. **TypeScript is strict** (`noUnusedLocals`, `noUnusedParameters`); unused
   imports break the build.
6. **Don't over-claim.** Several issues were partially done (see roadmap
   §Partial). If acceptance isn't met, mark it partial or not planned and say
   why. Never call model output “verified”.
7. **Respect the scope decisions** (ADRs 14–17): no Goethe lists, no full human
   verification (no reviewer), per-deck enable/new-day only (no interval
   overrides), no AI-authored German learning content without review, and no
   accounts/backend.

## Where code goes (`web/src/`)

- `lib/` — pure, unit-tested logic (no React): `srsCore`, `stages`, `stats`,
  `projection`, `grade`, `judge`, `selectors`, `store`, `data`, `cloze`, `gloss`,
  `search`, `i18n`, `cefr`, `tts`, `persist`, `backup`, `asr`, `shuffle`, `cn`,
  `theme`. **Put logic here**, add a `*.test.ts`.
- `components/ui/` — shadcn-style primitives (Button, Card/Stat, Tabs, Select,
  Switch, Progress, Accordion, Chip).
- `components/` — Art, ErrorBoundary, Onboarding, Shortcuts.
- `hooks/` — `useDeck`, `useProgress`, `useStudy`.
- `routes/` — one file per screen; wired in `App.tsx`.

State: `lib/store.ts` (observable over `localStorage["stufe-progress-v2"]`, read
via `useProgress()`), mirrored to IndexedDB and an optional backup file.

## Naming convention (grammar groups)

Bunpro style: **German pattern/formula is the title**, a short **English
function** is the `subtitle`, grouped level → lesson → point. E.g.
`Passiv: werden + Partizip II` — "passive voice". Keep it consistent across
levels.

## Environment: Windows + WSL

The agent runs on Windows; the repo lives in WSL (e.g. `~/projects/stufe`).

1. **PowerShell → WSL quoting is mangled** (`$VAR`, `$(...)`, quotes). Never
   inline complex bash — write a `.sh`/`.py` file and run
   `wsl -e bash -lc "bash /tmp/x.sh"`. Don't put `$?` in a `wsl -e bash -lc "..."`
   string (PowerShell expands it). Node via `nvm`.
2. **File ownership**: on this machine `write`/`edit` land as your WSL user
   (`ivaylo`), not root. If you ever see root-owned files, copy via
   `wsl -e bash -lc "cp <windows-temp> <dest>"`.
3. **Playwright** needs the Chromium system libs (`libnspr4 libnss3
   libasound2t64`); without root, `apt-get download` + `dpkg-deb -x` +
   `LD_LIBRARY_PATH` works.

## Commit / issue conventions

- Small, focused commits. `Closes #N` / `Refs #N`; commit messages via
  `git commit -F <file>`. **Verify** the tracker after pushing — `Closes #a #b`
  has silently closed only some issues.
- One logical change per commit; include the regenerated `data/` and `docs/`
  when content/build changes.
- Push directly to `main` (the project does not use PRs); Pages redeploys on push.
- Keep `documentation/` in sync when behaviour changes (not `TASKS.md`, which is
  just a pointer to the tracker).
